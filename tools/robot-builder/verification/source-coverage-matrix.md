# Robot Handbook construction coverage matrix

Review scope: Robot Handbook, Mongoose 2022. Acceptance scope: any supported legal new robot, with correct installation prerequisites, costs, capacity, relevant derived statistics and explicit operating conditions. This matrix does not require a general combat, medical, manufacturing, fleet or career simulator. "Verified" API status remains scoped to selected construction checks; catalogue row counts do not establish complete coverage.

Status key:
- I: Implemented and independently tested for the stated scope.
- P: Partial; specified construction choices, checks, derived outputs or operating conditions remain incomplete. Runtime simulation is not implied.
- A: A source ambiguity blocks an automatic answer, or requires an explicit disclosed interpretation.
- E: A selected construction answer depends on an external book, separate host/character input or an explicit referee decision.

## Immediate operational findings

1. Fixed and independently retested: biological coatings bypassed genome checks when installed through the default suite or separate instances. All routes now enforce the condition.
2. Fixed and independently retested: biological bodies could buy the cheap mechanical vacuum row, or gain free Slots by removing conventional internal power that their body rules do not establish. Both now block.
3. Fixed and independently retested: satellite uplinks accepted the default 5 km radio. Page 45 requires at least 500 km; independent instances now satisfy or fail the same check.
4. Fixed and independently retested: microbot options previously included slotted and biological-only hardware. Five forbidden candidates now fail through both editor and imported records; communication prerequisites, incompatible coatings and exclusive screen grades also fail correctly.
5. Fixed and independently retested: biological clone training previously accepted broad robot software bundles as one learned skill. Such bundles, including synthetic level-4 variants, are now rejected; an individual learned speciality still consumes the correct points.
6. Operational readiness is distinct from installation legality: robotic drone/swarm controllers need remote-ops software to function. A physically installed inactive controller must not be advertised as ready. Toolkit caps also apply in a task context, not as universal robot skill reductions.

## Meaningful completion gates

- Every selectable item must pass the same prerequisites, body restrictions, incompatibilities, quantity and pricing checks regardless of legacy selection, default-suite placement or independent instance.
- Unknown prerequisites or incompatible body geometry must block certification. A disclosed, inactive installation may be legal but must not be described as operational.
- Operational projections must separate software, characteristic DM, hardware skill, toolkit cap and situational modifiers. Never add alternative bonuses automatically.
- Unsupported special paths, source ambiguities and external host dependencies must remain visible for the selected design. A global warning alone is insufficient if a specific unsupported construction claim is being calculated. Documented situational conditions may remain outputs rather than executable task checks.
- Full construction-option coverage requires absent high-tech bodies/software, cyberlimbs and other relevant augmentation choices, converted vehicle options and selected external-host dependencies. It does not require combat resolution, medical outcomes, fleet simulation, retrofit histories, support procurement or full careers unless separately requested.
